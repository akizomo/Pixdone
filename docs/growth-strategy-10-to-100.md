# PixDone 成長戦略: 10 → 100ユーザー

> 期間: 2026年4月〜6月（約12週間）
> リソース: 週10〜20時間
> 目標: アクティブユーザー 10人 → 100人

---

## 現状分析

### プロダクトの強み

PixDoneはすでに**コアループが完成している**。これは大きなアドバンテージだ。

- Smash List + エフェクト（Common 12種 / Rare 8種 / Epic 6種 = 計26種）が動いている
- テーマ3種（Arcade / Synthwave / Forestbit）が切り替え可能
- ポモドーロタイマーが統合済み
- Stripe課金（¥600/月、¥6,000/年、7日間無料トライアル）が稼働
- PWA対応済み、日英2言語対応
- Vercelにデプロイ済み（pixdone.vercel.app）
- OGP画像・メタタグ設定済み

### プロダクトの弱点（成長観点）

| 課題 | 影響 |
|------|------|
| **シェア機能がない** | ユーザーが自発的に広めるフックがゼロ |
| **カスタムアナリティクスがない** | どこでユーザーが離脱するか分からない |
| **ランディングページが弱い** | PWAに直接入るが、未ログインユーザーへの訴求が薄い |
| **SEOが限定的** | PWA SPAのため検索流入がほぼ期待できない |
| **テーマが3種のみ** | 「もっと欲しい」と感じる前に飽きる可能性 |

### ユーザー獲得経路の現状

SNS投稿とProductHunt/noteから10人を獲得。これは**個人のネットワーク＋コンテンツマーケティング**が機能していることを示す。100人まではこの路線の延長で十分到達可能。

## 戦略の全体像

10→100は「プロダクトマーケットフィットの検証フェーズ」。広告やSEOに投資するのは早い。代わりに3つの柱で攻める:

```
┌─────────────────────────────────────────────┐
│         10 → 100 ユーザー戦略              │
├─────────────┬──────────────┬────────────────┤
│  ① 口コミ   │  ② コンテンツ  │  ③ プロダクト  │
│  の仕組み化  │   マーケ      │   改善        │
├─────────────┼──────────────┼────────────────┤
│ シェア機能   │ X/Twitter    │ オンボーディング│
│ エフェクト   │ note記事     │ リテンション   │
│ 共有        │ コミュニティ  │ アナリティクス  │
└─────────────┴──────────────┴────────────────┘
```

## 柱①: 口コミの仕組み化（最重要）

100人規模では「既存ユーザーが自然に広めたくなる仕組み」が最もROIが高い。

PixDoneのシェアのコアコンセプトは**「嫌なことを派手に破壊するカタルシスを見せびらかす」**こと。「5タスク完了しました」のような生産性マウントではなく、「確定申告をSupernovaで消し飛ばした」という**ネガティブ → ポジティブの感情変換**がバイラルの核になる。

見る側の心理: タスク名に共感する（「歯医者の予約」「上司への報告書」）→ エフェクト映像で目が止まる → 「自分もあの嫌なやつ、こうやって消し飛ばしたい」→ インストール動機。

### 1-A. コレクションからのエフェクトシェア

**工数目安: 10〜14時間**

コレクションタブで、所有しているエフェクトそれぞれに「Share」ボタンを配置する。

**UXフロー:**
1. コレクションタブ → 所有エフェクトの一覧
2. 「Share」ボタンをタップ
3. **テキスト入力画面**: ユーザーが自由にコメントを書く
   - プレースホルダー: 「一言どうぞ」
   - サジェスト例をタップで挿入可能（「ついに倒した...」「さよなら、」「二度と会いたくない」）
   - サジェストはあくまで起点。ユーザー自身の言葉が乗ることがコンテンツとしての強さになる
4. **GIF/短尺動画を自動生成**: エフェクト再生をMediaRecorder APIでキャプチャ（2〜3秒）
5. プレビュー確認 → Web Share API（モバイル）/ ダウンロード（PC）で投稿

**出力フォーマット: GIF or MP4（静止画ではない）**

PixDoneの魅力は「壊れる瞬間の動き」にある。静止画ではただのピクセルアートで「なんだこれ？」で終わるが、2〜3秒の破壊アニメーションはタイムラインで指を止めさせる力がある。技術的にはMediaRecorder APIでCanvas/DOM要素をMP4キャプチャするのが最も軽量。GIF変換は後から追加可能。

**シェア時の自動付与テキスト（編集不可部分）:**
```
#PixDone #今日の敵
pixdone.vercel.app
```

「#今日の敵」がフォーマットとして定着すれば、ユーザー同士でタイムラインが自然に形成される。

**なぜこの導線か:**
- タスク完了直後のシェアは「今忙しい」で見送られがち
- コレクションからのシェアは**いつでも能動的にできる**。タスク完了と関係なく共有の機会がある
- 「このエフェクト持ってるぜ」というコレクター欲の発露。ポケモンカードを見せびらかす感覚

### 1-B. 週次リキャップ — 「今週の最強の敵」

**工数目安: 10〜14時間**

毎週（日曜夜 or 月曜朝）にプッシュ通知またはアプリ内バナーで「今週の振り返り」を表示。ユーザーは今週完了したタスク一覧から**一番苦戦したタスク**を選び、**お気に入りのエフェクト**で改めて破壊してシェアする。

**UXフロー:**
1. 週次リキャップ画面が開く（今週完了したタスク一覧）
2. 「一番苦戦したタスク」を1つ選ぶ
3. 使用するエフェクトを**自分で選ぶ**（所有エフェクト一覧から）
4. テキスト入力（1-Aと同じUI。サジェスト＋自由記述）
5. 破壊エフェクト再生 → GIF/MP4自動生成
6. プレビュー確認 → シェア

**1-Aとの違い（重要）:**
- 日常のSmashはエフェクトが**ランダム**だが、週次リキャップではユーザーが**自分で選べる**
- ランダム性（日常）と選択の自由（週次）のコントラストが体験として気持ちいい
- 「こいつにはこのエフェクトを使いたい」という感情が生まれ、エフェクトへの愛着が深まる
- 1週間の振り返り自体がリテンションの儀式になる → **週次復帰率に直結**

**PixDone+への課金動機にもなる:**
- Rare/Epicエフェクトを持っていれば「今週の敵」をもっと派手に壊せる
- 無料ユーザーはCommonエフェクトだけで破壊するから、「あの派手なやつで壊したいな」が課金のきっかけ

### 1-C. 招待によるミニ特典

**工数目安: 4〜6時間**

招待リンク経由で新規登録が発生したら、招待者にCommonエフェクトのRareドロップ率を一時的に上昇させる（例: 24時間、Rareの確率を12%→25%に）。

PixDone+の無料期間延長よりも、**ゲーム内報酬**のほうがこのプロダクトに合っている。

### シェア機能の安全設計

タスク名にセンシティブな内容（人の名前、病名など）が入る可能性がある。対策:
- シェア前にタスク名を**編集可能**にする（デフォルトは元のタスク名が入る）
- 「タスク名を隠してシェア」オプション（エフェクト＋コメントのみ）

## 柱②: コンテンツマーケティング

SNS＋noteで10人獲得できた実績があるので、これを**体系化・継続化**する。

### 2-A. X（Twitter）での定期発信

**工数目安: 週2〜3時間**

効果的な投稿パターン:

| パターン | 例 | 狙い |
|----------|-----|------|
| 開発ログ | 「Epicエフェクト追加した。3%で出る。」| 開発者・ゲーマー層へのリーチ |
| エフェクト動画 | 30秒のスクリーンキャプチャ | 視覚的フックでRT獲得 |
| ユーザーの声 | 「使い始めて2週間の方から...」| 社会的証明 |
| 数字の公開 | 「ユーザー30人突破」| 成長ストーリーへの共感 |
| 比較・対比 | 「Todoistは管理するアプリ、PixDoneは壊すアプリ」| ポジショニング明確化 |

頻度: **週3〜5投稿**。毎日でなくていい。質 > 量。

ハッシュタグ案: `#PixDone` `#タスク管理` `#ゲーミフィケーション` `#個人開発` `#インディーゲーム`

### 2-B. note記事（月2本）

**工数目安: 月4〜6時間（記事2本分）**

記事テーマ案:
1. **「タスク管理に疲れた人へ — PixDoneという選択肢」** → 課題共感型。Todoistに疲れた層を狙う
2. **「個人開発でユーザー100人を目指す記録」** → 開発者コミュニティからの流入
3. **「ゲーミフィケーション × 生産性 — なぜ"壊す"が効くのか」** → 知的好奇心層
4. **「PixDoneの技術スタック全公開」** → 技術記事としてQiita/Zennにも展開可能

note記事 → X投稿で導線を作る。記事そのものがSEO資産にもなる。

### 2-C. コミュニティ参加

**工数目安: 週1〜2時間**

- **ProductHunt**: すでに投稿実績あり。アップデート時に再投稿またはコメントで存在感を維持
- **Reddit**: r/productivity, r/gamification, r/webdev に英語で紹介
- **Discord**: 生産性系・インディーゲーム系のサーバーで自然に紹介
- **Indie Hackers**: 成長ログを投稿（10→100の過程は人気コンテンツ）

## 柱③: プロダクト改善（リテンション重視）

新規ユーザーを連れてきても、残らなければ意味がない。**初回体験とリテンション**を優先する。

### ~~3-A. オンボーディングの改善~~ ✅ 完了済み

オンボーディング改善は実装済み。初回体験のRare/Epicブーストロジック（40/40/20）も稼働中。

### 3-B. ストリーク（連続利用日数）の導入

**工数目安: 6〜10時間**

毎日1つ以上タスクをSmashすると連続日数がカウントされる。

- ヘッダーにストリークカウンターを表示（🔥3 のようなシンプルなUI）
- 7日連続でRare確率ブースト（24時間）
- 30日連続でEpicエフェクト確定ドロップ
- ストリークは共有カード（1-B）にも表示される

ストリークはリテンションの**最も安価で効果的な手段**。Duolingo、Snapchat、GitHubが証明済み。

### 3-C. 基本アナリティクスの導入

**工数目安: 4〜6時間**

Vercel Analyticsだけでは不十分。最低限、以下のイベントをトラッキングする:

- 新規登録 / ログイン
- タスク追加 / Smash完了
- エフェクト表示（種類・レアリティ）
- テーマ変更
- ポモドーロ開始 / 完了
- シェアボタンタップ（追加後）
- 課金ページ閲覧 / チェックアウト開始

推奨ツール: **Mixpanel**（無料枠で月10万イベントまで）または**PostHog**（オープンソース、セルフホスト可）。

データがなければ戦略は勘でしかない。**これは後回しにしてはいけない改善**。

## 優先度マトリクス

最も重要なのは「何をやらないか」の判断。週10〜20時間では全部はできない。

```
            影響 大
              │
   ┌──────────┼──────────┐
   │ ストリーク │ シェア機能 │
   │ アナリ    │ 共有カード │
   │ ティクス  │          │
   ├──────────┼──────────┤
   │ SEO改善   │ 招待特典  │
   │ 新テーマ  │ note記事  │
   │ 追加     │          │
   └──────────┼──────────┘
              │
            影響 小
   工数 大 ←──┼──→ 工数 小
```

**最優先（Must）:**
1. アナリティクス導入 — すべての意思決定の基盤
2. コレクションシェア（1-A） — 口コミの起点。GIF/動画 + ユーザー自筆テキスト
3. ストリーク — リテンションの要

**重要（Should）:**
4. 週次リキャップ（1-B） — 「今週の最強の敵」を選んで破壊する週次儀式
5. X定期発信 — シェア機能と連動してユーザー投稿をRTする運用
6. note記事シリーズ

**余裕があれば（Could）:**
7. 招待特典
8. 新テーマ追加

~~オンボーディング改善~~ → ✅ 完了済み

## やらないこと（6月まで）

以下は**意図的に後回し**にする:

- **広告出稿**: 100人規模ではCPAが高すぎる。PMF検証後に検討
- **SEO本格対策**: SPAのSSR化は工数が大きい。note記事のSEOで代替
- **新テーマ大量追加**: テーマ不足で離脱しているかどうかはデータで判断。先にアナリティクスを入れる
- **React移行**: アーキテクチャ改善は成長に直接貢献しない
- **Phase 2/3機能**（Theme Progression, AI生成）: 100人のフィードバックを得てから着手
- **多言語対応の拡充**: 日英で十分。他言語は需要が見えてから

## リスクと対策

| リスク | 対策 |
|--------|------|
| シェア機能を作っても誰もシェアしない | シェア後にミニ報酬（エフェクト確率ブースト）を付ける |
| SNS投稿のリーチが伸びない | 動画コンテンツに注力（エフェクト映像は目を引く） |
| 新規は来るがリテンションが低い | ストリーク + オンボーディング改善で初週の体験を磨く |
| 週10時間しか確保できない期間がある | Phase 1（基盤）だけは必ずやる。Phase 3-4は縮小可能 |

## まとめ

PixDoneは**コアプロダクトが完成している**状態にある。10→100の壁は、プロダクトの問題ではなく**発見と定着の問題**。

やるべきことは3つ:
1. **測れるようにする**（アナリティクス）
2. **広まる仕組みを作る**（シェア機能 + 共有カード）
3. **続けたくなる仕掛けを入れる**（ストリーク）

この3つが揃えば、週10〜20時間のリソースでも6月末100人は十分に射程圏内。
