# PixDone コンバージョン分析レポート

**日付:** 2026年4月8日
**対象期間:** 過去7日間
**現状:** 42ビジター → 1新規登録（CVR: 2.4%）

---

## 1. ベンチマークとの比較

フリーミアムSaaSの業界ベンチマーク（2025-2026年データ）と比較すると、PixDoneの2.4%はかなり低い水準にある。

| 指標 | PixDone | 業界平均 | 上位パフォーマー |
|------|---------|----------|------------------|
| ビジター→サインアップ | **2.4%** | 3〜7% | 10〜15%+ |
| フリーミアム（オーガニック流入） | — | 13.3% | 15%+ |
| フリーミアム（広告流入） | — | 15.9% | 20%+ |

**結論:** 現状のCVRは業界下位。フリーミアムモデルの平均（13%）に対して約5分の1しかない。構造的な問題がある可能性が高い。

## 2. ファネル上の問題点（根本原因分析）

コードベースを詳細に調査した結果、以下の5つの主要なボトルネックを特定した。

### 問題① ランディング体験の不在（最重要）

**現状:** PixDoneには専用のランディングページが存在しない。ビジターが初めてアクセスすると、いきなりタスクリスト画面（空のTutorialリスト）が表示される。

**影響:** ビジターは「これは何のアプリか」「なぜ使うべきか」「何ができるか」を理解する手がかりがない。ヘッダーにロゴと「Sign up」ボタンがあるだけで、プロダクトの価値提案（Write → Smash → Reward）がどこにも表現されていない。

**根拠（コード）:**
- `App.tsx` のルーティングは `/` でいきなり TaskList を表示
- 未ログイン時のヘッダーは `En/Ja チップ` + `Sign up ボタン` のみ
- ヒーローセクション、デモ動画、機能紹介、スクリーンショットは一切なし

### 問題② サインアップ後のメール認証フリクション

**現状:** メール+パスワードで登録すると、メール認証が完了するまでログインできない。フローは以下の通り：

1. ユーザーがメール・パスワードを入力
2. Firebase が認証メールを送信
3. ユーザーは即座にサインアウトされる
4. メールの受信箱を確認し、認証リンクをクリック
5. 再度アプリに戻ってログイン

**影響:** 登録の「勢い」が完全に途切れる。メール認証を待つ間にユーザーが離脱するのは非常に一般的。特にモバイルではメールアプリとの往復が大きなフリクションになる。

**根拠（コード）:** `AuthContext.tsx` の `register()` → `sendEmailVerification()` → 即座に `signOut()` → `login()` で `emailVerified` チェック

### 問題③ CTAの訴求力不足

**現状:**
- ヘッダーの「Sign up」ボタンはラベルのみで、ベネフィットの説明がない
- しかも英語固定（`Sign up`）で、日本語ユーザーに対応していない
- チュートリアル完了パネルのCTAは「サインアップ（無料）」だが、チュートリアルを全部終えないと表示されない
- チュートリアルを途中で離脱した場合、サインアップへの導線はヘッダーのボタンのみ

**根拠（コード）:**
```tsx
// App.tsx L1096 — ヘッダーのCTAは英語固定
<Button variant="primary" onClick={...}>Sign up</Button>
```

### 問題④ プロダクトの価値を体験する前にサインアップを求めている

**現状:** ビジターはタスクを追加して「スマッシュ」体験ができるが、そのインタラクションの楽しさ（エフェクト、サウンド）がサインアップの動機として十分に活用されていない。

**影響:** 未ログイン状態でもCommonエフェクトは体験できるが、「なぜアカウントを作るべきか」の文脈が欠けている。タスクデータのクラウド保存、複数デバイス同期、テーマ変更など、サインアップの具体的なメリットが事前に伝わっていない。

### 問題⑤ ソーシャルプルーフと信頼シグナルの欠如

**現状:** ユーザー数、レビュー、メディア掲載、テスティモニアル等の社会的証明が一切表示されていない。

**影響:** 新規ビジターにとって、未知のアプリにメールアドレスを登録するハードルが高い。

## 3. 改善提案（優先度順）

### 🔴 優先度: 高（即効性あり）

#### 提案A: ファーストビュー体験の改善

未ログインビジターに対して、アプリ画面に入る前、または画面上部に「価値提案セクション」を追加する。

**実装案:**
- ヒーローエリアに「タスクを書いて、スマッシュして、ごほうびをもらおう」のタグラインを表示
- 3秒程度のエフェクトデモアニメーション（GIF/動画）を自動再生
- 「無料で始める」ボタン（日本語対応）

**期待効果:** ビジターが3秒以内に「何ができるアプリか」を理解できる。業界データでは、明確な価値提案の追加でCVRが20〜40%向上するケースが多い。

#### 提案B: メール認証フローの緩和

**実装案（2つの選択肢）:**

1. **推奨: Google OAuth を最優先の認証方法にする**
   - AuthModalでGoogleボタンを視覚的に最も目立つ位置に配置
   - Google認証ならメール確認不要で即座にログイン完了
   - モバイルでのフリクションが大幅に減少

2. **代替: メール認証を後回しにする**
   - 登録直後はログイン状態を維持（メール未認証でも使用可能にする）
   - 一定期間後（例: 7日以内）にメール認証を求める
   - タスクデータの同期やPixDone+の購入時に認証を必須にする

**期待効果:** サインアップ完了率を2〜3倍に向上させる可能性。認証フリクションの除去はコンバージョン改善で最もROIが高い施策の一つ。

#### 提案C: CTAの日本語化とベネフィット訴求

**実装案:**
- ヘッダーのCTAを `lang` に応じて切り替え: 「無料ではじめる」/「Start free」
- ボタン下に一行テキスト: 「タスクデータをクラウド保存」「複数デバイスで同期」
- チュートリアル完了を待たず、3タスク完了時点で軽量なサインアップ促進バナーを表示

### 🟡 優先度: 中（1〜2週間で実装）

#### 提案D: インタラクティブ・オンボーディングの導入

**現状の課題:** Tutorialリストはタスクが事前に入っているだけで、ガイド付き体験になっていない。

**実装案:**
- 初回アクセス時に「タスクを1つ追加してスマッシュしてみよう」のステップバイステップガイドを表示
- スマッシュ体験後に「楽しかった？ アカウントを作ればデータを保存できます」のCTAを表示
- プログレスバー（3ステップ中2完了）で達成感を演出

**期待効果:** ガミフィケーション型オンボーディングは、アクティベーション率を最大47%向上させるデータがある。PixDoneのコンセプト（タスク完了の満足感）と完全に一致する施策。

#### 提案E: 「お試し制限」の見える化

**実装案:**
- テーマボタンをタップした時、ロック状態のテーマプレビューを表示（現状はサインアップモーダルが開くだけ）
- Rare/Epicエフェクトが出る「はず」だったタイミングで「PixDone+ならRareエフェクトが見れた！」の通知を表示
- 3リスト制限に近づいた時に、リスト作成画面で残りスロット数を表示

### 🟢 優先度: 低（長期的な取り組み）

#### 提案F: ソーシャルプルーフの追加

**実装案:**
- 「○○人がタスクをスマッシュ中」のライブカウンター
- App StoreやGoogle Playのレビュー引用（該当する場合）
- 「メディア掲載」バッジ

#### 提案G: リファラル・メカニズム

**実装案:**
- 「友達を招待するとRareエフェクトを1つアンロック」のインセンティブ
- シェア機能（スマッシュ結果のスクリーンショット共有）
